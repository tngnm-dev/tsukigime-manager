# 設計メモ
このアプリで「なぜこう作ったか」をまとめたもの。コードのコメントに入りきらない判断を書く。

## 1. データの形
### 1-1. 日付と月を文字列（ISODate / YearMonth）で持つ
**決めたこと**
- 日付と月は文字列で持つ

**理由**
- 比較をする必要があるため、文字列(ISODate は "YYYY-MM-DD"、YearMonth は "YYYY-MM")で持つようにしました。桁がそろっているので、〇月5日と〇月10日の比較を容易に

**ほかの案と、選ばなかった理由**
- 案: `new Date()`の採用
- 選ばなかった理由: タイムゾーン変換が必要になるため
- 例：日本時間の4月1日を`Date`で作って`toISOString()`で文字列にすると、"2026-03-31T15:00:00.000Z"になる。UTC に直すときに日本時間はUTCより9時間進んでいるので、契約日や入金日がずれて月まで変わる可能性がある。

### 1-2. 料金を履歴（Fee）として持つ
**決めたこと**
- 駐車場の区画の料金は`Fee`配列で持つ

**理由**
- 料金未納状態で値上げあった場合や仲介手数料(契約初月のn倍)を処理する際に、正常な処理を行うためにこの形に決めました。

### 1-3. 入金と請求の間に割り当て（Allocation）を置く
**決めたこと**
- 入金と請求を直接つながずに、「どの入金の、いくらを、どの請求に充てたか」を1件ずつ`Allocation`として持つ。

**理由**
- 1つの入金が複数の請求を担っている場合がある。例：4/25の20,000円の入金が、仲介手数料10,000円 ＋5月分 10,000円。
- 1つの請求が、複数の入金に分けて払われる場合がある。例：5月分 10,000円を5,000円ずつ2回に分けて入金。
- 入金が請求より多い場合がある（余りが出る）。余りは、どの請求にも割り当てられていない残りとして表せる。

**他の案**
- `Deposit`に契約や対象月を直接持たせると、1件の入金と1件の請求が同じ金額で1対1に対応する場合しか表せない

### 1-4. 保存するもの／計算で出すもの
**決めたこと**
- 人が判断して入力したものは保存し、ほかのデータから必ず決まるものは保存せず、表示のたびに計算で出す。

**理由**
- `Deposit.excluded`（「この入金は割り当ての対象から外す」という人の判断）は、消すとほかのデータから復元できない。だから保存する。
- 「割り当て済みかどうか」は、入金・契約・`Fee` から必ず決まる。これを保存してしまうと、あとで `Fee` を直したときに、保存した値と計算し直した値が食い違う。
  - 例：4月の料金を 8,000円 → 10,000円 に直すと、本当は 2,000円 足りないのに「割り当て済み」のまま残る。

**ほかの案と、選ばなかった理由**
- 案：割り当て結果も保存して、毎回の計算を省く。
- 選ばなかった理由：データを直すたびに保存した結果も更新する必要があり、更新し忘れると食い違いが起きる。件数が少ないこのアプリでは毎回計算しても遅くならないので、食い違いが起きない方を選んだ。

## 2. 入金の割り当て

### 2-1. 充てる順番（一時金 → 古い月から）
**決めたこと**
- 入金の順番は一時金(仲介手数料や更新料)を先に充てる

**理由**
- 業務ヒアリングからの要望で、一時金の優先度を高くしています

### 2-2. 料金が未登録の月で止める
**決めたこと**
- 料金が未登録の月(`item.remaining === null`)があった場合、割り当てを止める。

**理由**
- 料金が未登録の月を飛ばすと、その月が未払いのまま先の月が埋まってしまうので止める。例: 8月が未登録だった場合に、7月/9月/10月が支払い済みで、8月が未払いになってしまう

### 2-3. 前払いはチェックを入れたときだけ
**決めたこと**
- 料金の前払いはフォームで事前にチェックを入れる
- 前払いのチェックで入るのは先の月の家賃だけ。将来の一時金は、期限が今月末までになったときにふだんの割り当てで充てる。

**理由**
- 前払いは通常の自動割り当てとは違い、ユーザーの確認を必要とする割り当てのためチェックを入れての割り当て処理にしています

**ほかの案と、選ばなかった理由**
- 案: 非延滞状態での入金は、自動で前払いにする
- 選ばなかった理由: 請求より多い入金があった場合に、別契約分(2区画契約など)や振り込んだ人が金額を間違えている可能性がある。この点はシステムでは判断できないため
- 案: 前払いの範囲に一時金もいれる
- 選ばなかった理由: 将来の更新料が今月の料金より先に入っていたため直した

## 3. 保存

### 3-1. 壊れた保存データはサンプルに切り替えずエラーにする
**決めたこと**
- 保存データが壊れていた場合、サンプルに切り替えずエラーにする

**理由**
- 本番（NAS）では保存データが読み込めなければエラーになり、サンプルに切り替えることはない。デモ版も同じ動きにして、本番でデータが読めなかったときの表示をデモで確かめられるようにした。

### 3-2. 保存キーのバージョン
**決めたこと**
- 保存キーはデモ版は localStorage のキーにバージョンを付けている。tsukigime-manager:v3を記載

**理由**
- 保存データの形が変わったとき、古いデータと区別するためにtsukigime-manager:v3を記載

### 3-3. DataSource 型と Promise
**決めたこと**
- 保存先の読み書きを DataSource 型（load と save）にまとめ、どちらも Promise を返す形にした。

**理由**
- 本番ではNASを使う。保存先を変えても、DataSourceの中身だけ差し替えればよいようにした。
- localStorage はすぐ読み書きできるが、NASでは読み込むのに時間がかかる。最初からPromiseにしておけば、呼び出す側（App.tsx）を直さずに済む。

## 4. 画面

### 4-1. 延滞は行の背景ではなく、支払状況のバッジと太字で目立たせる
**決めたこと**
延滞のときだけ「支払状況」をバッジ（薄い赤の背景・赤い枠・太字）に。支払詳細の文字も太字に。

**理由**
- 最初は行の背景を薄いピンク（#fff1f2）にした → 色味の違いしかなく目立たない
- 濃くすると、落ち着いた青の配色の中で浮く
- 強調をセル1つに絞れば、表全体の印象を崩さずに目に入る
- 色だけに頼っていない（「延滞あり」の文字と点もある）

### 4-2. 区画の表は番号順のまま（延滞順に並べ替えない）
**決めたこと**
駐車場のリストは延滞のある駐車場を上に出すが、区画の表は区画番号の順のまま

**理由**
- 延滞順に並べると、割り当てて延滞が消えた瞬間にその行が下へ動き、何が起きたか分かりにくくなる
- 延滞が 1・6・10番のように離れていても、4-1 のバッジで目に入る（サンプルの伊藤駐車場で確認）

### 4-3. 駐車場のリストは延滞のある駐車場を上に、最初に開く駐車場も延滞のあるところ
**決めたこと**
左のリストを「延滞ありの駐車場」と「延滞なしの駐車場」に分ける。何も選んでいないときは、延滞のある1つ目の駐車場を開く（なければ1つ目）

**理由**
今見ている駐車場とは別の駐車場の延滞を見落とさないように。どの駐車場を見ていても、延滞のある駐車場と区画の数が見える

## 5. CSS

### 5-1. 部品ごとのCSS Modulesと、全体用の普通のCSSに分ける
**決めたこと**
- 本番ではページが増える予定で、1つのCSSだとクラス名がぶつかる事故を命名の注意だけで防ぐことになるためCSS Modulesを採用。components部品の隣に○○.module.cssとネームして配置
- 全体用のcssはApp.tsxで読み込む

**理由**
- CSSはcomponentについて回るものなので、componentと同じ場所に置く。
- :rootの変数と、要素セレクタ（body など）はModulesにしても全体に効くので、普通のCSSに分けた

### 5-2. PCだけに対応する
**決めたこと**
1000px以下では区画詳細を表の下に回すだけ

**理由**
使うのは管理者2人で、職場のPCでだけ操作する前提

## 今後の改善点
- マイグレーション。古いバージョンのデータを新しい形に変換して読み込めるようにする

- 手動の割り当ては回数は少ないが大事な操作なのに、確定したあと画面が大きく変わって、何がどこに入ったのか分かりにくい
- 割り当てフォームを `<dialog> `に移し、同じ dialog の中で「入力 → 完了」と表示を切り替える。完了の表示に「何に何円入ったか」「入金の残り」「止まった理由」と「取り消す」ボタン

- 今は配列の順番がそのまま表の順番。あとから区画を足すと（欠番だった4番を戻すなど）表の一番下に出る
- 並べ替えるなら localeCompare(a, b, 'ja', { numeric: true })。文字のまま並べると "10" が "2" より前に来る（"A-10" と "A-2" も同じ）
- 区画番号は数ではなく名前として持つ（欠番や "A-1" 形式があるため）。id とは分けておく

- 入金の充て先は、業務のルールに合わせて、一時金 → 古い月の順に自動で決めている。
- 民法では、払う人が充て先を指定でき、指定がなければ受け取る側が指定できる。
- 契約者から「この入金は11月分」と指定されたときに、その月に充てる手段は今はない。
